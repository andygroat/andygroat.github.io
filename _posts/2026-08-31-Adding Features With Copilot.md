## Intro

This post follows on from my [previous post](https://andygroat.github.io/2026/08/26/Copilot-Instructions.html) in which I went through what I add to a `copilot-instructions.md` file to provide GitHub Copilot with context and rules to apply when working in the repositories. This post will look at the output that GitHub Copilot can now generate with this context.

![Copilot Working](/assets/post-images/CopilotWorking.png "Copilot Working")
<img src="/assets/post-images/CopilotWorking.png" alt="Copilot Working" style="width:100%; height:auto;" />

The repositories started with some very basic functionality for creating some todo items, retreiving them and marking them as completed. For this post I will extend the functionality of the APIs to allow the creation, deletion and retreival of shopping lists. These shopping lists will be able to have shopping list items, and there will be functionality for creating, deleting and retreiving shopping list items.

## The Plan

Since I am going to be adding a few new pieces of functionality to API, I don't just want to let Copilot loose on the code base, so I will switch Copilot from Agent to Plan, so then I can see what Copilot wants to do before letting it update the code base.

![Copilot Mode](/assets/2026-08-31/AgentSelection.png "Copilot Mode")

Now to give Copilot the prompt. Since we have already created the copilot-instructions.md, I don't need to further explain the architecture or coding conventions, or anything like that, I can get straight down to business and be specific about what needs to be built. So I have given this prompt to Copilot.

```
The api needs to be expanded to including shopping list functionality, there can be many shopping lists, and there should be the ability to create, get, update and delete shopping lists. The shopping list should have a title. Each shopping list can then have multiple shopping list items which should have a title and if it is complete.
```

That is enough to get Copilot started where it will expore the code base and instructions file. If Copilot needs any clarification prior to being able generate the report, it will ask questions. In the case of this prompt, Copilot then asked 5 further questions for clarification.

![Agent Questions](/assets/2026-08-31/AgentQuestions.png "Agent Questions")

Copilot then generates the plan for reviewing and refining if required. The generated report from this prompt can be found [here](/assets/2026-08-31/plan-add-shopping-list-and-shopping-list-item-features.md). The nice thing about viewing the plan is that you can see the instructions taking effect and the steps that Copilot will follow.

## The Implementation

I am happy with the plan generated by Copilot, so click the prompt to implement the plan and Copilot will switch into Agent mode and implement the plan as specified. You can view the progress Copilot is making as it builds up a list of files that it has updated or created.

![Agent Questions](/assets/2026-08-31/AgentImplementationOne.png "Agent Questions")

If the plan includes a lot of steps, or a lot of new files, Copilot will pause and provide a summary for what has been completed.

![Agent Questions](/assets/2026-08-31/AgentImplementationTwo.png "Agent Questions")

Finally, once all steps are completed, Copilot will notify.

![Agent Questions](/assets/2026-08-31/AgentImplementationThree.png "Agent Questions")

## Summary

This has been a short post, but it took considerably longer to create than it Copilot to add the new functionality to the API, which only took a few minutes to generate the plan, a review of the plan and then implementation.

I initially ran this prompt on the VSA API, but then took the exact same prompt and used on the Classic API. I ran through the same process of generating the plan, reviewing it and then getting Copilot to implement it. Thanks to the Classic repository having its own `copilot-instructions.md` file with its own rules and conventions to follow, Copilot then generated code that was appropriate to that API.

Happy Coding!
